# FIX-103 · The Bio player on a profile

## Current state

As of 24 Oct 2026, built by a Sonnet builder (T1), mobile `wmt/FIX-103` on `origin/main` `c47c9c84`. App code only: the Hub already serves the Voice Intro (backend `origin/main` `b2f4df6`), so no backend change. Status verifying. Not yet checked by a verifier.

| # | Before (`origin/main`) | After |
|---|---|---|
| 1 | M1 (my profile): a creator whose Voice Intro is made saw nothing under the bio; the app read `GET /me/voice-intro` only to decide the "Voice Intro" prompt | the Bio player under the bio (Play, 26 bars, the length, "Bio", the small "AI voice" tag), playing `audioUrl` from that same read |
| 2 | M5 (someone else's profile): `GET /users/{wawuId}/voice-intro` was typed and never called | the same player under the bio, playing `voiceIntro.url`, asked for once the profile is in, with the person's id |
| 3 | no way to hear a Voice Intro outside the maker's own VF11 | Play, Pause where it is, Play on, back to the start at the end; the clock shows the clip's length before Play once the file reports it |
| 4 | the Me tab stays mounted behind the other tabs | the clip stops when the tab or a screen is not in front, and does not start again by itself on return |

Boards (owned by DV2-03 and the profile tasks; this task lists none so each stays in one task): M1 and M5 draw the player between the bio and the social chips, and it is built there. M33 (About, as a visitor) draws no player; none is drawn there (its header is not the profile header). VF11 (Hear yourself) was built by VERIFY-03 and is unchanged.

States built, and the real cause of each:
- **none made** (a plain account, a creator with no intro, `voiceIntro: null`): nothing is drawn, no dead Play (R-47). On M1 the existing "Voice Intro" prompt still shows for a creator with none.
- **idle / paused**: Play, the bars filled to where it stopped.
- **loading**: Play was pressed and the file has not reported a length yet (the player's busy ring).
- **playing**: Pause, the bars fill.
- **error**: Play was pressed and the clip did not come in within 15 seconds (`BIO_LOAD_PATIENCE_MS`); the player's own "Couldn't play this. Tap to try again." row, and a tap asks for the clip again. The audio source reports no failure of its own, so the time is the signal.
- **the read itself failing or still on its way**: nothing is drawn (the profile stays as it is).

Route used: `GET /api/hub/users/{wawuId}/voice-intro` (`VoiceIntroPublicController`, VOICE-01), answering `{ voiceIntro: { url, aiVoice: true } | null }`, `404` for a person who is not there or who blocked the viewer. Takes the person's UUID (`wawuUserId`), not a handle. M1 uses `GET /me/voice-intro` `audioUrl` and `aiVoice` (already read for the prompt; now read for every creator, whether or not the screen can open the prompt).

Reused, nothing new: `VoicePlayer` (DV2-COMP), `AudioSource` (the feed's player: `expo-audio` on the phone, the audio element on the web). No new native module, so this ships over the air.

Open, for `tasks/SWEEP-ME.md` or the lead: (a) the Hub serves no clip length, so the clock reads 0:00 until the file's header is in (BACKEND_GAPS G-VERIFY-03-5, updated here). (b) The 15 second limit is a pacing figure of this task, not from a board. (c) NOT RUN: the live look on a local stack with the web export (a creator with a recorded Voice Intro, another person plays it; a creator with none shows no control) and the pictures of the built screens beside the boards: the builder ran out of its step budget before the stack was up. The boards were rendered and looked at (`scratchpad/fix-103-b/design/`, M1, M5, M33, VF11, dark and light). A phone: NOT RUN (no device).
