## Builder report, round 3

Fixed (before, then after; the verifier's repro is `scratchpad/me-04-v/r2/scripts/a4.py`, and the new spec `src/storage/tests/upload-late-file.contract.spec.ts` runs the same sequence against a loopback S3 host with the real SDK, a real database and a real PUT to the presigned link):
1. **Medium, a late PUT after a release was never counted or removed.** Before (a4.py on 607099c): 4 x (presign 20 MB, PUT, release, PUT again) left 85,983,232 bytes in the bucket and `usedBytes` 0. After: the Hub's own sweep (`src/storage/late-file-sweep.ts`, started every 10 minutes by `StorageSweepService`, job `sweep-late-uploads`) looks at every `abandoned` row (released by the person, or settled as never arrived) in `content/preview` and `content/full` whose link has expired: `createdAt` older than 300 s plus `UPLOAD_SWEEP_MARGIN_SECONDS` (default 600, so 15 minutes, the time `reconcileStale` gives a slow upload). If the object is in the bucket it is deleted and the row records it (`sweptAt`, `sweptRemovedAt`; a row whose file never came back gets `sweptAt` only). In the spec, 3 cycles of 20 MB leave 3 objects and `usedBytes` unchanged; the sweep at 4, 9 and 14 minutes does nothing; at 16 minutes it removes all 3 (3 deletes seen), `usedBytes` is unchanged, and a second pass sends nothing. A claimed key is left alone (a piece naming it: 0 deletes, the object kept, the row marked `sweptAt` only). Storage down: a HEAD that answers 503 leaves the row (`left: 1`, `sweptAt` null), a refused delete (500) leaves it too, and the next pass removes the file. A pending (counted) file, another person's rows and an abandoned row in `avatars` are not touched. The timer body never throws. A migration adds the three nullable columns (SHARED-CHANGES ME-04 #4).
2. **Low, merge risk with FIX-15's `POST /uploads/confirm`.** Backend `origin/wmt/FIX-15` (9070e5f) is merged into the branch (merge commit; conflicts in `contract/openapi.json`, regenerated, and `storage.controller.ts`, both routes kept). `POST /uploads/release` now sets `releasedAt`; `settleUpload` answers `abandoned` for such a row without asking the bucket, and `adoptArrived` re-checks it inside its lock. Before (the spec with the guard switched off): presign 30 MB, PUT, release, PUT again, confirm answers `confirmed` and `usedBytes` goes up by 30 MB. After: `abandoned`, `usedBytes` unchanged, through the key and through the fileUrl, also with the bucket down; a row first given up on by a confirm and then released stays released; an unreleased row that was given up on and then lands is counted by confirm as before. **ME-04 must merge after batch 3 (FIX-15, PR #138).**

Sweep (SWEEP-APP rows ME-04 R3-1 to R3-3): release vs create is not atomic (self-harm only); a draft walked away from keeps its file counted (a ruling); the late-file sweep sees a row once, so a PUT that began inside the link's life and finishes after the margin lands uncounted.

Checks (each gated on its log's EXIT line): backend tsc 0; eslint 0 on the 7 touched files; `src/storage` 10 suites, 198 tests pass (FIX-15's `upload-settle` and `storage-quota` among them, and the new 11); `contract:build` twice with the same hash, `/uploads/confirm`, `/uploads/release` and `/uploads/formats` in it; mobile contract synced from backend 13b7a13 (`contract/SOURCE_COMMIT`), `npm run api` regenerated the types (the sync also brings in what backend main added since 2a4b9a4), typecheck 0, `src/features/create` 2 suites 58 of 58, then the full check once: 157 suites, 2890 tests, gates 0 fail 5 warn, tasks ok, EXIT 0.
