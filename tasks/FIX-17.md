## Goal

FIX-07 fixed `/search`. Its verifier found 23 other GET routes that still answer 500 when a query or path value holds a NUL (Postgres error 22021): public (`/shop/products?search=`, `/shop/:id`, `/creators?category=`, `/learn/guides?country=`, `/users/public/:id`, `/content/public/creator/:id/content`), signed in (`/events?host=`, `/me/purchases?q=`, `/content?category=`, `/feed?category=`, `/feed/entries?category=`, `/services?category=`, `/services/mentors?category=`, `/users/:id/public-profile` and its `/profile-fields` and `/content`, `/legal/requests/:id` and `/contract`) and admin (`/admin/creators?q=`, `/admin/finance/wallets?q=` and `/:id`, `/admin/shop/products?search=`, `/admin/payments/receipts?txRef=` and `?flow=`). Also two non-NUL 500s: `GET /shop/categories/<not in the enum>/subcategories`, and `GET /admin/shop/orders` with an unknown `fulfilment` or a non-numeric `page` or `perPage`. And `GET /search/closest` has no length limit on `q` (an 8,000-token `q` costs 2.6 s of ILIKE work).

## Scope

One rule, applied once: a NUL (or anything else Postgres refuses in text) in a query or path value answers 400 naming the field, before any query runs, on every route. Prefer one global place (a pipe or middleware) over per-route edits, keeping every answer that is not a 500 today byte-identical, and pick the single NUL policy the code base follows from now on (today it is stripped in money and AI text, refused in legal documents, the assistant and profile audience, replaced in the Fintava webhook): write it in `docs/contract/CONVENTIONS.md`. The two enum and paging 500s become 400s naming the field. `closest` gets the same 100-character cap as `/search` (check the protected lock first; if it captures a longer `q`, stop and say so). Many of these routes are protected: every change is a former 500, and the PR lists them.

**The mechanism (answers to the brief).**
- *Where it is applied.* Only `src/main.ts` (one line, before `listen`). The production start is `node dist/src/main.js`; no second bootstrap exists. The other places that build a Nest app are 142 spec files, `src/openapi/emit-openapi.ts` (documents, no requests), a live-socket fixture, a PIN harness and four Fintava sandbox scripts; none applies the check except the builder's two specs. `applyHubHttpSettings(app)` is the shared place a spec harness reuses, and the check is not in it. So **the specs run without the check**. I installed it on every spec's app (`NestApplication.prototype.init` hook, `js/prod-check-setup.js`) and re-ran the full suite: two specs assert answers production no longer gives (D2). The protected suite is also built without it, but passes 253/253 with it.
- *Order against the other pipes.* Read from Nest 11.2.1 (`router-execution-context.js`): per argument the pipes are `global.concat(paramPipes)`, so the global `ValidationPipe` (with `transform`) runs first, then the argument's own (`ParseUUIDPipe`, `TgifDatePipe`, `ParseEnumPipe`), then this one, last. Arguments are resolved with one `Promise.all`. My sweep confirms it: 1,193 NUL requests that were `Validation failed (uuid is expected)` on main, 280 `uuid v 4`, 899 `property x should not exist`, 546 `perPage must not be greater than 100`, 94 `date must be a day`, and so on, stay byte-identical on the branch. The only 400s of main that change are the 90 `cursor is not one this server gave out` or `this list gave` (a handler's own check, after the pipes) and closest's.
- *"Waits one turn".* On a bad value the pipe returns a promise that settles after `setImmediate`, then throws. Every other check of the request settles through microtasks (class-validator, the parse pipes; there is no async validator in the code base), so a fault in another argument rejects the `Promise.all` first and its 400 is the answer, as before the task. A NUL cannot reach a query this way: the handler runs only after the `Promise.all` resolves, which needs this pipe's promise to resolve, which it never does for a bad value. Mutants V6 (one microtask) and V7 (no wait) are killed.
- *Ways around the pipe.* Nothing reads the query or a path value outside a decorated argument: the only `@Req()` are the Fintava and Nuvion webhooks (raw body and headers); no guard reads `query` or `params` (they read the user, headers and the raw body); the only `createParamDecorator`s return the user, the admin or the open wallet; no middleware beyond helmet, compression and cookie-parser; the live socket reads an `Authorization` header or a first frame. Guards run before pipes and keep their answer (anonymous on a signed-in route is 401, a person without a wallet is 409, roles 403: byte-identical in the sweep). Controllers are read from `ModulesContainer` at call time, so every module Nest knows is covered; the app has no lazy module. **But the router reads the arguments at `app.init()`, so the call must come before it, and nothing in the tests pins that (D1).**
- *Routes registered after the call.* None exist (no `LazyModuleLoader`, no raw Express routes; `emit-openapi` aside).
