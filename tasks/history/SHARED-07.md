- **Page cap: 400** (`PDF_MAX_PAGES`). A 300-page book is read whole with room above it; a file that claims more shows its first 400 pages and builds no more. The count is read as `Math.min(Math.floor(doc.numPages), 400)`. A count that is not a whole number of at least 1 (0, negative, NaN, Infinity) posts `pdf:failed`, so the phone's viewer takes it. On the old code `Infinity` looped for ever in the page.
- **Load timeout: 45 seconds** (`PDF_LOAD_TIMEOUT_MS`), in the reader (`Pages`), Android only. If neither `pdf:ready` nor `pdf:failed` arrives, it calls the same `outside()` every other failure uses (phone viewer opens, reader closes). Ready clears the wait (the effect depends on `pagesShown`); a `handedOver` flag makes a failure plus the timeout open the viewer once. iOS reports its own load and has no timer. 45 s is long enough for a large file on a slow connection (a premature hand-over only moves the person to the phone viewer, which loads the same file).
- **Tests (13 new), shown failing on the old code first** (the two constants were present but unused): 8 failed. `pdfPage.test.ts`: a claimed 1,000,000 pages builds at most 400 and posts READY (old: 1,000,000 built); a 300-page file builds 300; claims of 0, -3, NaN, Infinity, undefined and '12' post FAILED and build none (old: READY or an endless loop, the stand-in stops it at 2,000,000). `PdfReaderPhone.test.tsx` (fake timers): the phone viewer opens and the reader closes at 45 s and not at 45 s minus 1 ms (old: never). These pass on the old code by nature and pin the new behaviour: ready before the timeout cancels it, a failure then the timeout opens the viewer once, a closed reader does not wait, iOS has no timeout.
- **Mutants (9, all killed):** ready not cancelling, a failure not flagged, no handed-over guard, timeout minus 1 ms, timeout on iOS too, timer never cleared, cap off by one, no cap, no count check.
- **Low to the sweep:** iOS has no short-circuit for a non-web address (SWEEP-APP, Open lows, SHARED-07 #1). Not fixed here, as ruled.
