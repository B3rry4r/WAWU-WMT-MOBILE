Findings

- **M1 medium, defect.** `src/user-profile/signup-identity.service.ts` lines 54 and 112: `handle: { equals, mode: 'insensitive' }` is sent as `ILIKE`, so `_` (allowed in a username) matches any one character. Repro: a person holds `sg_wXild`; `GET /users/handle-available?handle=sg_wXil_` returns taken, and `PUT /users/me/identity {handle:"sg_wXil_"}` from another account returns 409 "That username is taken". The same wrong refusal shows in A3 (typing and Continue). Fix: compare `lower(handle) = lower($1)` (raw), and add a spec with an underscore.
- **M2 medium, unclear (lead ruling; PATCH /users/me is protected).** Edit profile has neither the case-insensitive rule nor the reserved words, so R-82's "unique ignoring case" holds only on the sign-up route. Repro: A holds `Pat1`; B `PATCH /users/me {"handle":"pat1"}` returns 200 (two holders; `handle-available` then answers taken for both). `wawu` or `admin` pass the same way (code reading). The claim route says "Change it in Edit profile", so Edit profile is where a held handle is changed.
- L1 low: the reserved list lacks `me`, `root`, `www`, `settings`, `login`, `join`, `null`, `undefined`; `wawu.official` and `Wawu_` are free; `.`, `..` and `_` are valid handles (the same character rule as Edit profile). The list is marked PROVISIONAL(SIGNUP-RESERVED-HANDLES).
- L2 low: `POST /auth/signup` now answers 400 for `firstName` or `lastName` that is empty, not a string or over 80 characters; main ignored them. No client sends them today (the web uses `/auth/register`, the app sent no names before).
- L3 low: `PUT /users/me/identity` accepts any characters in a name (markup passes; a NUL byte gives 502 "Your name could not be saved"). Same as `PATCH /users/me`.
- L4 low (read, not run): after a wallet is open the names can still be changed to anything, as before through `PATCH`. The wallet's own names are not touched: the Hub keeps none (the opening sends them to the provider once), and the route only writes WAWU ID's name. Money views that show a person's name read WAWU ID live, so a rename changes what a payee sees (as with `PATCH`).
- L5 low: `GET /users/handle-available` can be walked at 60 a minute per address (20 a second). It answers existence only, with no id. The public profile route is by id, but any signed-in account can already look a handle up (`user-profile.service.ts` line 308), so the new exposure is existence for people with no account. Acceptable for the shown `wawu/<handle>`.
- L6 low: sign-up now needs the Hub to answer before WAWU ID is asked (A3 Continue calls `handle-available` first); not run with the Hub down.
- Test gaps: the Hub spec has no ThrottlerModule, so the 60 a minute limit is untested there (verified live); no spec for an underscore in a name (M1); the full jest run is load sensitive (`schoolsScreen` SC10).
