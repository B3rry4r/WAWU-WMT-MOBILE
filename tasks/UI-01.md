### Findings
- F1 defect: the back icon is an arrow (arrow-left with tail). W9 and A3 draw a chevron (`ChevronLeft`, design/_gen nav helper). Seen in `showcase-dark.png` against `W9-dark.png`. Icon set needs a chevron-left, used by IconButton `back`.
- F2 defect: field hint and error text use the 13.5 secondary style; the design field hint is 12.5 (caption size), the label 13 (built 13.5), and the value 15.5 (built 16). Measured: "Must be the number on your BVN" is about 204 px wide built against about 189 px on A3. Field corner radius is 18 in the design (`field` helper) and 16 here (`radius.input`).
- F3 defect (web): a focused text field also shows the browser's own outline inside the box (white in dark, black in light), on top of the purple ring (`states-dark.png` Email crop). A3 shows only the purple ring.
- F4 defect (web): a Button takes the focus ring on a mouse click and keeps it after the click ("Tap to load" still ringed after loading ends, `ld2-dark.png`). A ring should show for keyboard focus only. Native is not affected as far as I can reason, NOT RUN.
- F5 unclear (owner): `Money` is kobo, but the live API sends whole naira. Until MONEY-04's kobo contract lands, every caller has to multiply by 100, and the doc comment "as the API sends it" is untrue today. Which unit the wallet endpoints will send is the fact that unblocks it.
- F6 differs-for-recorded-reason: naira sign from the platform font (D15, BRIEF section 1 "The ₦ symbol"). Seen in both W1 and the build, the sign looks heavier than the digits in both.
- F7 unclear: sizes in Button (34/44/54, 13.5/14.5/16, 15/17/19), TextField height 54, ring width 1.5, skeleton width `size * 7`, and Money minor scale 0.72 are numeric literals in component files, not tokens. The gates pass, and these match the design's px, but CLAUDE.md says spacing and radii come from `@/theme`. `layout.controlH` is 48 and `tapMin` 44, neither is 54.
- F8 unclear (test strength): tests are written as "a user can ..." and the loading/disabled tests would fail if the guard were removed (onPress would be called, busy state absent). They do not assert the D15 platform font on the sign, the kobo scale and opacity, or the Button focus ring, so a regression there would pass. Positive signed amounts speak as "2,000 naira" with no "plus".
- Builder's recorded differences: button side padding on the nearest token (differs-for-recorded-reason only if the owner accepts 16/20/24 against 14/18/24: no decision cites it, so unclear but minor; invisible in my captures); focus ring without the glow (no RN value for `--accent-glow`; in the web capture it is a solid purple ring and looks right, so acceptable, unclear whether a decision is needed); glass IconButton uses `surfaceScrim` (in `showcase-light.png` the glass button is grey on a light page and the "Glass" large button is white on white, nearly unreadable; it is meant for covers, so I judge this unclear until a screen on a cover uses it).
- Light-mode design shows soft shadows under the secondary buttons and cards (W1-light); the built secondary buttons have only the hairline. Minor, unclear whether the shadow token is meant to carry over.

### NOT RUN
