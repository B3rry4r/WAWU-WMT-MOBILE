### Findings

- **D1 · defect (backend, ME-11's change): the works routes now hang when WAWU ID stalls.** `GET /users/{wawuId}/featured-works` and `.../{workId}` call `lookupPublicIdentities` for `owner`, and that `fetch` has no timeout. Reproduce: sign in, then `kill -STOP` the wawu-id process (it still accepts connections but never answers) and `curl -m 40 .../users/<id>/featured-works`: no answer in 40 s on the list and on the detail (http 000 both). With wawu-id down (connection refused) the same call answers 200 with the handle as the name, as the code comment says. Before this change the works routes never waited on WAWU ID. The same unbounded call exists in chat and professional code, so the fix is a timeout in `WawuIdClient` (fenced `src/common`) or a bounded wait in `ownerView`; the lead decides which.
- **D2 · defect (mobile): more than 8 files gives a developer sentence.** Choose 9 photos on M36 (all upload), Save: the banner reads "media must contain no more than 8 elements" (the Hub's validator text, lower case). M36 has no limit on files and no wording for it. Fix: stop at 8 (the Hub's `MAX_WORK_MEDIA`) or write the sentence in words.
- **D3 · defect (mobile, dead end): the cap sentence promises a removal the app cannot do.** At 50 works Save shows "A profile can feature at most 50 works. Remove one to add another." and nothing in the app removes a work (G-252). Fix: owner's call on wording, or the remove control.
- **D4 · defect (minor, mobile and backend): bytes that are not an image are accepted as a photo and draw a blank box.** `evil.jpg` (HTML bytes, browser type image/jpeg) presigns, uploads, passes `confirmUpload` (a HEAD only) and saves; M34's card, M35's hero and M36's preview then show an empty box with no icon (a work with no media shows the placeholder icon). The Hub never reads the bytes (same on avatars). Fix: a decode-failure fallback in `WorkCover` and `MediaPicker`; server-side sniffing is the owner's call.
- **D5 · unclear (backend wording): a link of 301 to 1000 characters gives "Link can be at most 300 characters", over 1000 gives the raw "link must be shorter than or equal to 1000 characters".** Both land under Link; the second is the DTO's text. Same for an empty body or a non-string title ("title must be shorter than ..."), which the app cannot send.
- **T1 · test gap (backend spec):** replacing the owner's `avatarUrl` with the stored value survives `profile-work-owner.contract.spec.ts` (no test stores an avatar). Live, the avatar is a fresh signed link.
- **T2 · test gap (ME-16 spec):** removing `wawuUserId: owner` from the work lookup survives both works specs, although the live code is correct (404 `Work not found`, shown above). The new `owner` makes this leak louder.
- **T3 · test hygiene (ME-16 spec, not ME-11's):** `profile-works.contract.spec.ts` leaves one `ProfileView` row and one `StorageObject` row (content/preview) in a seeded database.
