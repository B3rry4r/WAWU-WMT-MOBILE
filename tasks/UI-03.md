### Accent pill contrast (builder's open question)

Measured from the captures: accent pill text #9411C9 on its tint is 2.57:1 in dark (tint pixel 25172C) and 5.12:1 in light (tint ECDEF2). Other tones, computed from the same tokens: dark positive 8.78, warning 8.75, danger 6.03, info 8.35; light positive 3.26, warning 2.87, danger 3.65, info 3.60 (12.5 px bold, so none of the light status tones reach 4.5:1). The kit draws it exactly like this: `design/_gen/kit.js` `pill` writes in `var(--accent)`, and the dark artboards SH3 (WAWU pick) and SH9 (On its way) show the same dim purple. The design system's own note in `design/_ds/wawu/tokens/colors.css` says `--accent-fg` (#C368EA in dark) is "purple used AS TEXT/ICON on dark (contrast-safe)", which gives 5.24:1 on the same tint, and the kit's own `going` chip uses it. No entry in DECISIONS.md or docs/designer/BRIEF.md covers this. Judgement: not a build defect (it matches the kit); finding 7, unclear for the owner.

### Findings

1. **defect.** Option chip label colour when not selected. Kit `optChip` (events.js line 28) sets no colour on an unselected chip, so it inherits primary text (dark ink on light, near white on dark; E8-light shows "Past" and "Conference" in ink). The build reuses the row chip's `textSecondary` (rgb 90,87,102 light, 169,165,180 dark). Visible in E8 against the showcase side by side (`ev/options-*.png`). The row chip is right as it is (kit `Chip` uses text-secondary). Not caught by any test (revert R10 passes).
2. **defect (small).** Option chips are 2 px wider than the kit. Kit: padding 14 and the outline as an inset shadow, so "Upcoming" is 94 px wide in E8; build: padding 14 plus a real 1 px border on each side, so 96.2 px (Past 59 vs 57, Conference 104 vs 101). Height is right because the box is border-box. Wrapping positions in the sheet shift by the same amount. The existing row chip has the same pattern (15 plus 1 across) from UI-02; not part of this diff but worth one fix for both.
3. **defect (minor, R-22).** The new constants cite `kit.js` `pill` and `events.js` `optChip` by name but not by line, and R-22 says "cite the kit line" (pill is kit.js line 57, optChip events.js line 28; Avatar cites its line).
4. **unclear (report accuracy).** Builder's report says M1 draws a 22 px name tick and a 21 px prompt tick. The kit draws `tick('creator', 20)` (me.js line 15) and `tick('pro', 24)` (me.js line 18); 22 and 21 are the visible extents. It also says the showcase tick (14) was compared with W7's Chidi Eze row, but W7 draws the default 15; the component default is 15 and the shape, colour and stroke match, so no component defect. Builder also says W7 has six recipients including lilac; W7 draws five (green, sky, pink, coral, lemon). None changes the verdict on avatars and ticks.
5. **unclear (low).** On the web the pill's `accessibilityLabel` lands as `aria-label` on a role-less div and the icon svg has no `aria-hidden`; the text is still read. On Android `accessible` groups it into one node. Needs the Android build to judge (NOT RUN). Test gap: removing `accessible` does not fail any test (finding 6).
6. **unclear (low, test gap).** `chips.test.tsx` does not assert the option chip's unselected label colour or that the pill is one accessible node; both reverts passed. The "ticks against the kit" test checks test ids and token equality only, so a changed tick size or stroke would not fail it. The tick is not this task's build, so no action needed beyond awareness.
7. **unclear (owner, rule 7).** Accent pill in dark is 2.57:1 as the kit draws it; the design system says use `accent-fg` for text on dark. Also light status pills (warning 2.87, positive 3.26, danger 3.65, info 3.60) are under 4.5:1 as drawn. Designer or owner to rule; building to the kit is correct until then. Unblocking fact: a ruling on whether the pill's accent ink is `accent` or `accent-fg`.

differs-for-recorded-reason: none. BRIEF has no W7 entry; its M1 entry (three tabs, R-9) does not touch avatars, ticks or chips.
