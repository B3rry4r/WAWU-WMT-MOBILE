**Findings**
1. **defect (blocking at merge): blocked people appear in the new directory routes once main is merged.** Reproduction: resolve the one conflict as in A above and run `vp02-blocked.spec.ts` (`blocked-A.txt`): `GET /professionals/directory` (field filter, with a token) lists a professional the caller blocked and one who blocked the caller, `total` counts them, `GET /professionals/directory/{id}` answers 200 for both, while `GET /professionals` hides them. Fix: take the viewer in both, pass it to `pageOf` (applied there so the web's list and the app's directory share it) and `detail`, read `@CurrentUser()` in the two controller methods, and add a spec for it (resolution B passes it, `blocked-B.txt`).
2. **defect (blocking at merge): `ProfessionalLocation` is not decided in the data export.** Reproduction: merge main and run `src/data-export-request/tests/data-export-map.spec.ts`: 1 failure, `undecided` is `["ProfessionalLocation"]` (`specs-merge-A.txt`). 3. **defect: the migration's timestamp sorts before main's newest.** `20261003181500_professional_location` against `20261004141500_legal_documents` and four more `20261004*` folders on main; the common rule (and the SHARED-CHANGES row, which still says it "sorts after main's newest migration (`20261003160000`)") needs it after every folder on main. Fix: rename to a timestamp after `20261004141500` when merging main, and correct the row.
4. **defect (low): impossible reply times read as the fastest figure.** Reproduction (`probe/p3_reply.txt`, pro 3): three `responded` messages whose `respondedAt` is before `sentAt` show `usualReplyMinutes: 1`, `answeredMessageCount: 3`, because `Math.max(1, ...)` clamps a negative median to 1; without the clamp (mutant 5) it is negative minutes. Both timestamps are written by the server today, so it needs clock skew between instances or backfilled rows, but the one figure a card must never invent is a flattering one. Fix: count only rows with `respondedAt >= sentAt`.
5. **defect (low): a city is only a length.** Accepted and returned (`probe/p1_city.txt`): `"​​"` (two zero-width spaces, blank on the card), `"Ikeja\n\nPay me directly on 0803"` (a new line and contact details beside a paid-message card), `"12345"`, `"<script>alert(1)</script>"`. Fix: reject control and format characters and require a letter; collapse inner whitespace.
