- App: `src/features/chat/` only: `AttachSheet` (two rows), `attachments.ts` (the four calls in order: where to upload, the PUT, `/uploads/confirm`, the message; the link), `pickAttachment.ts` and `.web.ts` (expo-image-picker and expo-document-picker, already installed; no new native module), `AttachmentBubbles.tsx`, `PhotoViewer.tsx`, `useChatThread` (`sendFile`: one `clientMessageId` per file, the upload kept after a refused send so Try again does not upload twice, a file on its way never holds up the next text), `ChatScreen`. A photo is written again without where it was taken (the 8 Oct ruling, `readPicked`).
- Limits and their source (`CHAT_LIMITS`, PROVISIONAL): PDF 20 MB (the I13 board's figure, nothing else names it); photo or video 100 MB (what a picture or video in a message or on a work already has); types PNG, JPEG, WebP, MP4, MOV and PDF (the chat folders' list since INBOX-06); a link lives 15 minutes (the Hub's other short read links).
- Not built, as drawn nowhere (R-47): the person picker for compose and the "..." menu (G-882 stays open for those two); I10's + in a paid question's reply (G-FIX-104-5).

## Goal

A person can send a photo, a video or a PDF to one person in a one to one chat, and that person can see it and open it. Nobody else can get a link to it.

## Scope

Backend: `src/chat/`, `src/storage/storage.service.ts`, `contract/openapi.json` (regenerated). Mobile: `src/features/chat/`, the contract copy and `src/api/schema.generated.ts`, `BACKEND_GAPS.md`, `SHARED-CHANGES.md`. No schema change, no migration, no fenced app file.

## Capability checks

- [x] A user can open Add to chat and see Photo or video and File, with File's line from the Hub (jest, live walk).
- [x] A user can pick a photo or a PDF, see it as sending, and see it sent; the other user sees it and opens it (jest, live walk with two sign-ins).
- [x] A third person cannot get a link to either file (live walk: 404, 404, and 404 for the chat; spec).
- [x] A file over the limit or of a refused type is refused with the Hub's sentence and posts nothing (jest, spec, live walk).
- [x] An upload the storage host turns away, or a send the Hub refuses, can be tried again without sending twice (jest: same message id, same upload kept).
- [x] A chat upload counts toward the sender's storage on the chat path and is refused when it does not fit; the web's usage and content presign are unchanged (spec).
- [x] A failed upload tried again, and a failed bubble deleted, give the Hub's count back; a landed file nobody sent is given back after a day (jest, spec).
