## What the backend serves today (from the analysis)

- **M11**: partial. Missing: Ticks, prices, expiry, eligibility and KYC status are served. NOT served: any benefit beyond the tick and hosting events. Upload cap is flat 5 for everyone, storage is flat 2 GB for everyone, ranking has no verified boost. The '25 uploads / 10 GB / reach' promises have no mechanism.
- **M12**: partial. Missing: No pay-from-wallet path: the tick is bought through a Flutterwave hosted/inline checkout, and there is no endpoint that debits the user's wallet to pay WAWU. Also, the wallet exists only for creator accounts (CreatorWallet) so a professional-only or user account has no wallet to pay from.
- **M13**: missing. Missing: No transaction PIN anywhere: needs set-PIN, verify-PIN (hashed, attempt-limited, lockout), reset-PIN, and the wallet-debit it authorises. Likely shared with the Wallet flow (A1).
- **M14**: served. Missing: Grant + expiry served (for the Flutterwave path only; wallet path absent, see M12).

A missing or partial row is yours to fix in the backend as part of this task (or the backend task listed in depends_on, check its owner in the task file). Never change the screen to fit the API.
