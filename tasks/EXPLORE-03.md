**Defaults (agent), owner may override.**
1. The creator taxonomy is the twelve A12 interest chips, ids in snake_case, label as drawn, in a kept list (`PROVISIONAL(EXPLORE-TAXONOMY)`; G-180).
2. A creator is in a category when a profile interest equals the id or the label, ignoring case; nothing is inferred (G-181).
3. The new lists use the same card as `GET /creators` (`wawuId`, `name`, `handle`, `avatarUrl`, `field`, `pieceCount`, `verification`, `following`) and the same eligibility: a creator profile with at least one live piece, and a creator nobody can name is dropped after the count (as `GET /creators` does). They also drop people hidden by a block (either way, no 404 tell) and people who switched off "show me in member lists".
4. `GET /explore/creators` is a new route with strict validation (category exact, `perPage` 1 to 50 default 24, `page` 1 to 10000). The older `GET /creators?category=` is unchanged because the web calls it.
5. Featured: one row per creator, `position` 0 to 1000 (default 0, lowest first, ties by time then id), `limit` 1 to 20 default 10. Only an existing creator account can be featured. `DELETE` is idempotent. Superadmin only, like `PUT /admin/policies/:slug`.
6. `FeaturedCreator` is OWNED in the purge map (the row goes with the creator); it is not exported (EXPORT_EXCLUDED: an admin choice with the admin id, not the person's content). `featuredByAdminId` is not a user reference.
7. Public text (names, handles) is returned as JSON strings only; nothing is rendered or marked up here.
