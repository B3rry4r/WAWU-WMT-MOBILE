## What the backend serves today (from the analysis)

| artboard | backend | what is missing |
|----------|---------|-----------------|
| M11 | partial | Ticks, prices, expiry, eligibility and KYC status are served. NOT served: any benefit beyond the tick and hosting events. Upload cap is flat 5 for everyone, storage is flat 2 GB for everyone, ranking has no verified boost. The '25 uploads / 10 GB / reach' promises have no mechanism. |
| M12 | partial | No pay-from-wallet path: the tick is bought through a Flutterwave hosted/inline checkout, and there is no endpoint that debits the user's wallet to pay WAWU. Also, the wallet exists only for creator accounts (CreatorWallet) so a professional-only or user account has no wallet to pay from. |
| M13 | missing | No transaction PIN anywhere: needs set-PIN, verify-PIN (hashed, attempt-limited, lockout), reset-PIN, and the wallet-debit it authorises. Likely shared with the Wallet flow (A1). |
| M14 | served | Grant + expiry served (for the Flutterwave path only; wallet path absent, see M12). |

A missing or partial row is not a reason to change the screen. Build it as designed against the contract and file the gap.
