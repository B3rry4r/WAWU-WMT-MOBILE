### How it is built (one shared helper, no copies)

- `src/features/device-approval/credential.ts`: `Credential`, `credentialHeader()` (the PIN header, or the signed approval of exactly this request), `isApprovalStop()`, `stopCode()`, `noRecordToForget`, `approvalRefused()` (`403 device_approval_refused`), `part()` (path parts encoded as the API client encodes them, so the signed path is the sent path).
- `src/features/device-approval/PayPinSheet.tsx`: the PIN sheet of every payment: it takes the screen's one `run(credential)`, shows the key only when this account has an approval key on this phone, and reads the sheet's own approval line as the prompt text. No sheet forks `PinSheet`.
- Each payment call: `& Credential` in place of `pin`, the header made first, `ApprovalStopped` added to its outcome type, `device_approval_refused` read as `approval_failed`. `sendPayment` (tips, unlock, paid ask) does this once for the three.
- Each flow: `submitPin(pin)` became `run(credential)`; right after the call, `if (isApprovalStop(outcome)) return notApproved(stopCode(outcome), earlierTry, forget)`, before any other answer. `earlierTry` is read BEFORE the try writes anything (an attempt held, an intent stored as unknown, `sent` set). `forget` is the flow's own `nothingMoved` where the try wrote a stored intent (tickets, school fees, plans, points pack, conversion, shortfall); where the only record is the attempt (its key and quote: tips, unlock, paid ask, credits, pass, request pay, legal) there is nothing separate to let go of and the attempt stays (`noRecordToForget`), so the PIN that follows is sent under the same key and quote.
- Default (lead), owner may override: a first try that was closed or refused leaves a held attempt (key and quote) in the flows whose only record is the attempt. The next Pay reuses it; if its quote has run out the Hub answers `quote_changed`, the attempt is freed and a fresh quote is asked. Money is safe either way; the choice keeps the key stable.

## Goal

A person who turned on fingerprint or face in Wallet settings approves every payment with it, not only the sends; the PIN is always the way back, and a closed or refused fingerprint never changes what the app holds for the payment.

## Scope

`wawu-wmt-mobile` only: the files above and their tests.
