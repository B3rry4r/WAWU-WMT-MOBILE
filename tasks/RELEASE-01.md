## Goal

The stores need listings, screenshots and privacy answers before they will review anything. This takes longer than people expect.

## Scope

The Google Play listing, its data-safety form (BVN, NIN, selfie, payments), screenshots from the real app, and an
EAS production profile pointing at production. Testing and the first release are Android (R-24); the App Store
listing waits for RELEASE-03. Submission is the owner's alone, from their own machine, with the store keys kept
off Expo (`docs/BUILDS.md`).

## Capability checks

- [ ] A production build installs from Play internal testing on the owner's Android phone and reaches the production backend.
- [ ] The Play listing is complete and passes Google's own pre-submission checks.

### Findings

**D1 · defect (medium): B2 and section 8 are stale against main; SETTINGS-02 is `done`.** `PLAY-LISTING.md` section 0 B2, the claims table and `DATA-SAFETY.md` D-3 all say SETTINGS-02 is `todo` and that "SETTINGS-02 serves it; the URL below points at it". SETTINGS-02 merged on 4 Oct (mobile a4f1148, backend a94f338): the app has About, Terms and Privacy policy screens (`src/features/about/`, routes `about`, `terms`, `privacy-policy`) fed by public `GET /about` and `GET /policies/{slug}` on the Hub. That does not clear B2, and the file must say why: (a) those routes return JSON, not a web page, and Play's privacy policy field needs a public page that loads without sign-in; (b) `available: false` until the owner writes the legal text with one `PUT /admin/policies/{slug}` (BACKEND_GAPS G-140), so today there is nothing to show; (c) the Terms and Privacy text must match `DATA-SAFETY.md`. What B2 needs now: the owner's text (G-140), that text entered through the admin PUT so the app shows it, and a public web page carrying the same text whose URL goes in Console (the web's `/privacy/policy` answers 307 to a generic terms page that names no BVN, NIN, selfie or Fintava). The file should also stop calling SETTINGS-02 `todo` and drop it from the "what unblocks it" cell.

**D2 · defect (low): the form omits things the app collects.** Sign-up asks for a **password** (`SignUpScreen.tsx`, "Password") and the account type, and neither appears in any row; the professional licence number and issuer (PROS-03, P6) are not in "Other info"; an event's street address is public typed text and is not mentioned. Add a row for each and say which Console category it is declared under (a password has no Play category of its own: name the one the Console help text points to).

**D3 · defect (low): section 5 (Permissions) is wrong in one place.** It says `expo-updates (none)`; `node_modules/expo-updates/android/src/main/AndroidManifest.xml` declares `ACCESS_NETWORK_STATE`, and `expo-image` declares `INTERNET` and `ACCESS_NETWORK_STATE`. Both are normal permissions needing no Play declaration, so no answer changes, but the list is stated as complete. The section also says "Android adds INTERNET for any app" while `expo-image` already adds it. Correct the list and keep the instruction to read the real manifest after the build.

**D4 · defect (low): the target API level is not mentioned.** Google rejects uploads below its current target API level. The app is fine today: React Native 0.86's `gradle/libs.versions.toml` sets `targetSdk = "36"` and `compileSdk = "36"` and Expo SDK 57 builds with it, so this is a missing checklist line, not a blocker. Add it to the owner checklist (read Play's required level on the day; the first upload will be refused with a clear message if it moved).
