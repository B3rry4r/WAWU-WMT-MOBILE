## Findings

1. **medium** Files taken out of the draft keep counting against the account's storage, and nothing releases them.
   Where: `src/features/create/PreviewScreen.tsx:137` (Remove the preview), `UploadScreen.tsx:48-59` (picking another file replaces the draft's full file); backend `src/storage/storage.controller.ts` has no delete or release route (only presign, formats, usage, allowance).
   Repro (`scripts2/leak.py`, log `logs/leak.log`): creator, one 5 MB full file kept, then three 2 MB previews each picked and removed: `GET /uploads/allowance` usedBytes 11,535,017 (6 MB of removed previews still counted), 4 StorageObject rows, draft shows no preview. With 100 MB PDFs each wrong pick burns 100 MB of the 1 GB a free account has, and the Hub then answers "only 0 bytes of your 1GB storage is free" with no way to recover except a tick. A failed PUT plus Try again reserves twice too, but an object that never landed is settled by the reconcile job after 15 minutes; a landed one is not.
   Fix options for the lead: a route that releases the caller's own unattached `content/*` object (called from Remove and from replace), or do not count objects the create call never claimed.
2. **low** M19: the lone Service tile is wider than the other two (186 px against 170 px at 390 wide), so the "third tile's width" fix does not hold. `CreateScreen.tsx:122-123`: the tile has 16 padding with `flex: 1` (basis 0) and the empty spacer has none, so the tile takes the padding on top of its share. Picture: `shots2/cmp-M19-light.png`, `shots2/sheetA.png`. The artboard has four tiles, so only the width, not the placement, is unchecked against a drawing.
3. **low** No check of the upload slots before the upload. At "5 of 5 used" (`CreatorState.slotsUsed = 5`) M19 still opens Content, M21 still uploads and storage is reserved; only ME-08's create call can refuse. The comment in `upload.ts` says the Hub refuses "a piece over the account's upload or storage limit" at presign; presign checks storage only (`storage.service.ts:473-499`). Picture `shots2/M19-full-dark.png`. Sweep item, or ME-08.
4. **low** A PUT that fails after every byte went (storage answers 500) leaves the row at "100%" with a red bar above "That file did not upload. Try again." (`UploadScreen.tsx`, failed branch keeps `share`; `shots2/sheetB.png`, third panel).
5. **low** Routes are not gated by account type: a `user` account that opens `/create` directly reaches the tiles and uploads (rows grew); the Hub's presign has no creator check either, also true on main. The button itself is correct. Related: `draft.ts` is module state reset only by the Content tile, so a draft survives sign-out (read from code, not run).
6. **low** (automation only) A double click on the M21 drop box opened two file choosers and made two presigns; `choose()` only guards `stage.state === 'uploading'` (`UploadScreen.tsx:78`). The second send aborts the first, whose reservation stays. A real file dialog is modal, so a person is unlikely to reach this.

Pre-existing on main, reported apart: the storage quota is check-then-insert (`storage.service.ts:473` then `:499`), so parallel presigns overshoot. Twelve parallel 300 MB presigns against 1 GB: main accepted 7 (2.1 GB reserved), the branch 4 (1.36 GB). Not changed by this branch.
