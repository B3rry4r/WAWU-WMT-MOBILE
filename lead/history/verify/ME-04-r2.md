## Findings

1. **medium** `POST /uploads/release` does not stop a late PUT: a presigned link stays valid for 300 s after the release, so the file lands again in the bucket while its row is `abandoned` (not counted). Deterministic quota bypass with no ceiling: presign (counted), PUT, release (uncounted), PUT again; repeat. Nothing ever settles it: `reconcileStale` (storage.service.ts, `status: 'pending'` only) skips `abandoned`, and FIX-15's `settleUpload` only acts when the client calls confirm.
   Where: `src/storage/upload-release.ts:89` (delete, then `updateMany` to abandoned), `src/storage/storage.service.ts` reconcileStale.
   Repro: `scripts/a4.py` (log `logs/a4.log`): 4 x (presign 20 MB, PUT, release, PUT again): bucket holds 85,983,232 bytes, `GET /uploads/allowance` usedBytes 0. My stand-in does not check signatures; real storage honours a presigned PUT until `X-Amz-Expires=300`, so this shows the Hub's accounting, not the storage's acceptance. The honest app cannot reach it (Remove and the drop box are off while uploading, and leaving aborts the XHR).
   Fix options: a sweep that deletes the object of an `abandoned` `content/*` row still present after the link's life (also covers the walk-away leak in finding 3), or release only marks `abandoned` and the sweep deletes after 6 minutes.
2. **low** (SWEEP-APP R2-4, now with numbers) release vs create is not atomic and create never reads the row: 40 parallel rounds of create(piece with key K) and release(K): 39 times both answered success (listing on a deleted file, row `abandoned`), once 409. 25 staggered rounds (create up to 20 ms later): 25 both succeed, i.e. a create after a release is accepted. Self-harm only (own key). `content-piece.service.ts:515` create; `content-media.service.ts:182` frames already refuse `abandoned`. `scripts/a3.py`.
3. **low** (SWEEP-APP R2-3, confirmed) a draft walked away from keeps its file counted for good: sign-out (`draft.ts:80` resetDraft, by ruling) or an app reload mid-draft: used 2,097,323 before and after, row `pending`, 0 releases sent (`scripts/c3b.py`). After the 15 minute reconcile it becomes `confirmed`, with no key left to release.
4. **low** merge note, not run: after wmt/FIX-15 merges, a late-landing file plus `POST /uploads/confirm` on a released row goes through `adoptArrived` (abandoned row, bucket present, fits) and is counted again. ME-04's app never calls confirm, so only a mixed flow reaches it.
